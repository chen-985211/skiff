# 测试策略

生产行为必须按 Red → Green → Refactor 推进。Red 表达用户可观察行为，失败应来自尚未实现的功能，而非环境故障或无意义断言。记录实际运行结果，不把补测描述成测试先行。

优先最低有效层：纯规则用 unit；用例用端口替身；RPC、仓储和恢复用 integration；模块依赖用 contract。关键下载流程同时使用真实 aria2 与本地 HTTP 服务证明，外部网站不能作为自动测试依赖。

测试时间由可观察条件决定成功，deadline 仅决定失败；不以固定等待时间推断下载完成。独立临时目录与受管子进程必须注册清理。无覆盖率百分比门槛，不以与实现同构的断言追求数字。
