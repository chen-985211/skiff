## 0.1.1 续传失败回归

用户复现 Cloudflare `__down` 在 45% 暂停后继续失败。读取引擎日志确认错误码 8，Range 请求从 4456448 开始，返回却从 0 开始。独立区间请求也返回 HTTP 200 整份响应。

先增加并运行 6 项回归测试，观察到：结构化错误丢失、仍提供无效普通重试、界面没有从头下载入口、适配器没有新目标与单连接参数；两类真实服务（忽略 Range / 返回错误 Content-Range）均复现同一无效失败状态。之后实现错误分类、聚合动作策略、显式重启用例与确认界面，目标测试转绿。

真实链路测试校验从头下载的完整字节、目标文件与原部分文件不同，并校验原部分文件在操作前后逐字节不变。现有支持 Range 的暂停、进程重启、续传和普通 404 重试测试继续保留。

再以失败测试锁定两个升级场景：旧版本缺少错误分类的失败记录仍可显式从头下载；aria2 session 不能把已完成/失败历史重新变成暂停任务。通过应用层恢复对账清除终态任务的运行时副本，不删除下载文件。

## 2026-11-18 历史失败任务与卡片工作台
